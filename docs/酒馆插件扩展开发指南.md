# 酒馆插件扩展开发指南（FlyAI L1）

本指南面向想把自己写的 SillyTavern 前端扩展跑在 FlyAI 上的作者。
**只支持没有 ST 主页面 DOM 依赖的逻辑型扩展**；UI 型扩展会被标记为 L2/L3。

## 1. 包结构

```
my-extension/
  manifest.json
  index.js
  style.css        # 可选
  templates/...    # 可选，入口用 fetch 读取
  assets/...       # 可选
```

打包成 zip 后上传（设置 → 酒馆扩展 → 安装，管理员）。zip 可以带一层顶层目录，
也可以直接是上述文件。

限制：≤500 个文件、解压后 ≤20MB、单文件 ≤5MB；拒绝符号链接/设备文件/路径穿越。

## 2. manifest.json

ST 原字段保持不变：

```json
{
  "display_name": "My Logic Extension",
  "version": "1.0.0",
  "js": "index.js",
  "css": "style.css",
  "author": "you",
  "loading_order": 100,
  "hooks": { "activate": "init", "enable": "onEnable", "disable": "onDisable" },
  "flyai": {
    "host_api": 1,
    "compat": "logic",
    "capabilities": ["chat.read", "variables.read", "settings", "slash.register"]
  }
}
```

- `js` 必填，必须是包内相对路径；
- `hooks.activate` 指向入口模块导出的函数名，加载后 `await` 调用；
- `flyai.compat`：`logic` / `panel` / `ui`，`ui` 不会被加载；
- `flyai.capabilities`：不声明就无法调用对应 RPC（`settings` 建议声明）。

## 3. 能力表

| 能力 | 允许的 RPC |
|---|---|
| `chat.read` | `chat.getMessages` |
| `chat.write` | `chat.setMessages/addMessage/deleteMessages`（当前 L1 返回不支持） |
| `variables.read` / `variables.write` | `variables.get/set`（会话 MVU `stat_data`） |
| `worldbook.read` / `worldbook.write` | `worldbook.list/get`；写回未实现 |
| `generate.quiet` / `generate.raw` | 作者生成桥（不产生用户楼层） |
| `prompt.inject` | `prompt.setExtension`（当前返回 false） |
| `settings` | 扩展命名空间设置读写 |
| `storage` | 账号级 KV（占位） |
| `net` | 宿主代理 `net.fetch`（仍受管理员 `st_net` 总开关与白名单） |
| `slash.register` / `slash.execute` | 命令注册与执行 |
| `ui` | `ui.toast` / `ui.popup` |

网络：扩展内 `fetch` 被拦截；跨域请求只能走 `net.fetch`，请求头仅透传
`Accept`/`Content-Type`，`Cookie`/`Authorization` 一律丢弃；密钥永远拿不到明文。

## 4. 可用模块

入口可以像在 ST 一样 import：

```js
import { eventSource, event_types, extension_settings, saveSettingsDebounced } from '../../../../script.js';
import { clamp, deepMerge } from '../../../../scripts/utils.js';
import { SlashCommandParser } from '../../../../scripts/slash-commands/SlashCommandParser.js';
import { SlashCommand } from '../../../../scripts/slash-commands/SlashCommand.js';
```

相对层级按 ST 的 `public/scripts/extensions/third-party/<name>/` 深度写即可；
FlyAI 的 import map 会把最终 URL 映射到本地 shim。

完整模块/符号清单见 `docs/酒馆插件兼容矩阵.md` 与
`docs/酒馆插件模块与符号覆盖矩阵.md`。不在清单里的符号会在安装报告里列为缺口。

## 5. 典型写法

### 事件 + 设置

```js
import { eventSource, event_types, extension_settings, saveSettingsDebounced } from '../../../../script.js';

extension_settings['my-ext'] = extension_settings['my-ext'] || { count: 0 };
eventSource.on(event_types.MESSAGE_RECEIVED, () => {
  extension_settings['my-ext'].count += 1;
  saveSettingsDebounced();
});
```

### Slash 命令

```js
SlashCommandParser.addCommandObject(SlashCommand.fromProps({
  name: 'hello',
  helpString: 'say hello',
  callback: (named, args) => `hello ${args.join(' ')}`.trim(),
}));
```

在聊天输入框输入 `/hello 世界` 即由扩展接管（不会发给模型）。
支持 `|` 管道与 `key=value` 命名参数；高级 STscript（if/while/闭包）未实现。

### 静默生成

```js
import { generateQuietPrompt } from '../../../../script.js';
const text = await generateQuietPrompt({ quietPrompt: '给我一句天气播报' });
```

生成走当前会话模型，不产生聊天楼层，受用户模型与 token 限制。

## 6. 调试

- 设置 → 酒馆扩展 → 详情：查看每个模块的 ✓/△/✗ 与缺失符号；
- 启用后宿主创建隐藏 iframe，加载/运行错误会记录在管理面板（最近 50 条）；
- 扩展内 `console` 不直连父页面，需用 `toastr` 或宿主 RPC 提示；
- `window.__FLYAI_EXT_HOST__.request(method, params)` 是底层桥，优先用标准 ST API。

## 7. 明确不支持

- `#extensions_settings` 等 ST 主页面 DOM、jQuery/Popper 布局；
- 任意远程脚本 `import()`；
- 读取密钥明文、Cookie、登录态；
- Extras / 服务端 Node 插件 / 真实 tokenizer；
- 附件上传、数据银行、Moving UI、拖拽面板。
