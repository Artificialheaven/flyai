# 报告：约会大作战「推进一轮」提示词与小手机数据流

- 日期：2026-11-24
- 对象：`show/P-v1.png`（约会大作战P-v1，JS-Slash-Runner 4.12.2 脚本）
- 结论均以当前 `chat-web` 代码 + 卡内脚本静态核对为准

## 1. 「推进一轮」实际怎么生成提示词

调用链：

```
卡面板按钮
  → context().generate("normal", { automatic_trigger: true,
                                   quiet_prompt: <场记/去处指令>,
                                   quietToLoud: true })
  → authorRuntime.requestGenerateMain()  （postMessage: flyai-author-generate-main）
  → CardAppFrame：generateCardReply(sessionId, { quietPrompt, automaticTrigger })
  → POST /api/chat（普通聊天生成，会产生新楼层）
  → run_agent_loop 组装真实提示词
```

关键点：

1. **走的是主聊天生成，不是独立文本生成**：会产生一条新的 assistant 楼层，派发 `MESSAGE_RECEIVED`，与用户手动发消息同一条管线。
2. **`quiet_prompt` 不落库**：`agent/loop.py` 只在出站请求的最后一条消息副本后追加（没有末条时新增一条 user 消息），history 与磁盘都不写。面板的「场记/去处」因此是一次性指令。
3. **提示词主体仍是标准装配**：
   - system：角色卡 system/persona + 世界书常驻条目 + 预设 main + **MVU `stat_data` 变量**（`build_system_prompt(variables=...)`）；
   - history：当前线程消息（按 `keep_turns` 截断，群聊按 actor 隔离）；
   - PHI：角色卡 `post_history_instructions` 紧跟历史；
   - `depth_blocks`：世界书 `@depth` / 预设 depth 块按深度插入；
   - 末尾才是 `quiet_prompt`（最后一条消息副本）与工具续轮 nudge。
4. **宿主能力不足时的降级**：卡内逻辑检测不到自动推进接口会抛出
   「当前宿主未暴露自动推进生成接口，请改用「挂入下轮」后在输入框发送。」；
   离线/正在生成时也有对应拦截。
5. 由于提示词是动态装配，**同一张卡不同轮的实际 prompt 不同**。可用新加的
   「查看提示词」按钮（消息操作栏）查看某条回复当时的 system/history/tools/参数快照。

## 2. 小手机内容是否进入主对话 AI 的上下文

有两条独立通道，**都不会以聊天消息形式写进 history**：

### 通道 A：MVU 变量（主通道）

- 小手机的会话数据存于会话 MVU `stat_data`（手机存档/联系人/往来等键）。
- 每轮 `build_system_prompt(..., variables=mvu_vars)` 会把变量树渲染进 system prompt。
- 因此主对话 AI 能看到手机的当前状态；卡内脚本用 `getVariables/updateVariablesWith`
  写的手机数据，下一轮即可见。
- 注意：写入的是 `stat_data` 变量树，不是 `chat_metadata.variables` 的兄弟字段
  （历史差异见兼容复核报告 #9）。

### 通道 B：手机主线摘要 + EJS

- 卡面板通过 `POST /api/sessions/{sid}/author/state`
  `{ phone_mainline: "..." }` 写入 `session.attributes.author.phone_mainline`（上限 128KB）。
- 提示词侧 EJS 的 `context.phoneMainline` 来自该字段；模板里
  `await globalThis.DALPhoneMainline.read()` 由模板沙箱注入，返回同一份摘要。
- 只有**被 EJS 模板引用时**才会进入提示词；它不是普通 system 段落，也不会进 history。
- 输出侧（消息渲染）目前不注入该桥，卡面板自身用作者运行时里的 `DALPhoneMainline` 读取本地数据。

## 3. 对测试的启示

- 验证「推进一轮」：在会话里点一次，观察是否新增楼层，再用「查看提示词」确认
  `quiet_prompt` 出现在最后一条消息尾部、且后续轮次不再出现。
- 验证小手机：改一次手机状态 → 下一轮提示词 system 段应出现对应 `stat_data`；
  若卡模板用了 `DALPhoneMainline`，还需确认面板已同步 `phone_mainline`。
- 若发现手机内容没进上下文，优先查 `stat_data` 是否真的写入、面板是否调用
  `/author/state`，而不是查聊天历史。
