# 酒馆插件兼容施工方案

- 版本：v1（2026-11-24）
- 配套文档：
  - `docs/酒馆插件加载可行性评估.md`（结论与证据）
  - `docs/酒馆插件模块与符号覆盖矩阵.md`（38 个宿主模块、184 个符号的逐项覆盖）
- 目标读者：FlyAI 前后端工程师
- 约束：Python 3.9 语法；前端沿用现有 `webapp` 技术栈；不修改现有卡内运行时的默认行为

## 0. 结论与范围

### 0.1 结论

**不追求“现成酒馆扩展装上就能跑”。** 采用“分级兼容 + 能力声明 + 扩展宿主”的方案：

- 先做 **L1 逻辑型扩展**：不依赖 ST 主页面 DOM，只使用事件、变量、世界书、生成、slash、设置；
- 对 UI 型扩展提供 **L2 面板协议**，不仿真 ST 主页面；
- 明确拒绝 L3（依赖 ST DOM/CSS/布局的扩展）；
- 所有网络、密钥、文件能力都走宿主，扩展代码永远拿不到登录态。

### 0.2 本期范围

| 范围 | 内容 |
|---|---|
| 做 | 扩展安装/更新/删除/启停、manifest、扩展宿主 iframe、模块注册表、事件总线、slash 子系统、设置持久化、受控网络、兼容诊断、管理 UI |
| 不做 | ST 主页面 DOM 仿真、ST 服务端插件、Extras、Node 服务端扩展、任意远程 Git 直装（首期只收 zip）、扩展自动更新市场 |
| 不动 | 现有 `cardApp` / `authorRuntime` 的默认路径；扩展宿主作为独立入口 |

## 1. 兼容等级与验收定义

### 1.1 等级

| 等级 | 定义 | 代码运行位置 | 本期 |
|---|---|---|---|
| L0 | 角色卡内 `tavern_helper` 脚本 | 现有作者/卡内 iframe | 维持现状，不回归 |
| L1 | 逻辑型扩展：无 DOM 依赖，使用事件/变量/世界书/生成/slash/设置 | 扩展宿主 iframe（隐藏） | **主目标** |
| L2 | 面板型扩展：使用 FlyAI 面板协议或独立面板 iframe | 扩展宿主 iframe + FlyAI 原生面板 | 可选第二阶段 |
| L3 | UI 型扩展：依赖 ST DOM、jQuery 选择器、`#extensions_settings`、ST CSS | 不运行 | **明确不支持** |

### 1.2 等级判定

由 manifest 声明 + 安装时静态扫描 + 运行时诊断三部分组成：

1. 安装时扫描所有 JS 的 `import` 语句，得到模块/符号缺口报告；
2. 若引用 `popup.js`、`slash-commands/*`、`RossAscends-mods.js` 等 UI 相关模块，标记 `L2/L3` 风险；
3. manifest 的 `flyai.compat` 只能“降级声明”，不能把实际 L3 扩展提升为 L1；
4. 运行时捕获 `error` / `unhandledrejection`，把失败原因写进扩展状态。

### 1.3 L1 验收定义

一个扩展满足以下全部条件，才标记为 `L1 可用`：

- 能加载并触发 `activate` hook；
- 能收到至少 `MESSAGE_RECEIVED` / `GENERATION_ENDED` 事件；
- 能读写聊天变量；
- 能调用一次静默生成并拿到文本；
- 能注册并执行一个 slash 命令；
- 设置能跨刷新/设备持久化；
- 不发起任何未经宿主代理的网络请求；
- 卸载后不残留定时器/监听器。

### 2.1 关键设计决策

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-1 | 不加载 JS-Slash-Runner 扩展本体 | 它依赖整套 ST 主页面；现有项目已选择重写 TavernHelper API |
| ADR-2 | 扩展宿主与卡运行时分离 | 生命周期、权限、加载顺序完全不同；避免污染现有卡兼容路径 |
| ADR-3 | 多文件扩展直接按 ST 路径静态加载，不强制打包 | 保留相对 import、动态 import、模板/资源；避免引入 Node 打包链 |
| ADR-4 | 不仿真 ST 主页面 DOM | UI 扩展兼容无边界；改为 L2 面板协议 |
| ADR-5 | 网络/密钥/文件全部宿主代理 | 扩展是远程可执行代码，不能拿 Bearer、Cookie、密钥明文 |
| ADR-6 | `script.js` 等模块按“扩展实际 import 的符号”优先补齐 | 覆盖率表显示先补 33 个高频符号即可显著提高启动率 |

## 3. 关键技术选型：扩展代码怎么加载

这是整个方案最需要先验证的点。推荐 **方案 A（ST 路径静态加载 + CORS）**，保留方案 B（安装时打包）作为回退。

### 3.1 方案 A：ST 形状静态路径 + CORS

后端把扩展文件挂在与 ST 相同的路径：

```text
GET /scripts/extensions/third-party/<name>/index.js
GET /scripts/extensions/third-party/<name>/style.css
GET /scripts/extensions/third-party/<name>/templates/foo.html
```

扩展入口在 iframe 内用绝对 URL 动态加载：

```html
<script type="importmap">
{"imports": {
  "https://<app-origin>/script.js": "data:text/javascript;base64,...",
  "https://<app-origin>/scripts/utils.js": "data:text/javascript;base64,...",
  "...": "..."
}}
</script>
<script type="module">
  import('/scripts/extensions/third-party/<name>/index.js')
</script>
```

为什么这样能工作：

- 扩展文件在自己的 URL 下，`import '../../../script.js'` 会解析成 `https://<app-origin>/script.js`，正好命中 import map；
- import map 把这些 URL 映射到本地 `data:` 模块，扩展无需真实存在 ST 文件；
- 扩展自己目录下的相对 import（`./src/foo.js`）解析到同目录静态资源，无需打包；
- iframe 是 `sandbox="allow-scripts"` 的 opaque origin，拿不到父页面 DOM、Cookie、localStorage；
- 模块脚本按 CORS 抓取，静态路由返回 `Access-Control-Allow-Origin: *` 即可；扩展资源本身是公开代码，不含用户数据。

需要验证的点（M0 spike）：

1. opaque-origin iframe 能否加载应用源的 ES module（CORS + `Origin: null`）；
2. import map 的绝对 URL 键是否按预期命中；
3. 扩展目录内的相对 import / 动态 import 是否正常；
4. CSS `<link>`、模板 `fetch` 是否受 CSP 影响；
5. 移动端 WebView（APK）下是否一致。

### 3.2 方案 B：安装时打包（回退）

如果方案 A 在某个运行环境（旧 WebView、CORS 限制）不可用：

- 安装时把扩展打成单入口 ESM（esbuild 或等价的构建步骤），把扩展内部相对 import 内联；
- ST 核心模块仍由 import map 提供；
- 模板/资源转成内嵌资产表，由 `renderExtensionTemplateAsync` shim 读取；
- 代价：需要 Node 构建依赖或浏览器内 wasm bundler，首期不作为默认路径。

### 3.3 不允许的加载方式

- 不允许扩展从任意远程 URL `import()`（只允许应用源的 `/scripts/extensions/...`）；
- 不允许 `allow-same-origin`；
- 不允许扩展直接 `fetch` 外网；
- 不允许在父页面执行扩展 HTML/JS。

## 4. 扩展包与 manifest

### 4.1 磁盘布局

```text
data/extensions/
  registry.json                 # 全局安装清单：name/version/source/sha256/installed_at
  installed/<name>/
    manifest.json               # 扩展自己的 manifest（保留 ST 字段）
    files/                      # 扩展全部文件，原样保存
    compat-report.json          # 安装时静态扫描结果
  logs/<name>.log               # 可选：安装/加载错误
data/<uid>/extensions/
  state.json                    # 该用户启用列表、顺序、设置
```

### 4.2 manifest 兼容字段

保留 ST 原字段，保证扩展作者不用改包：

```json
{
  "display_name": "Example",
  "loading_order": 100,
  "js": "index.js",
  "css": "style.css",
  "author": "someone",
  "version": "1.0.0",
  "homePage": "https://github.com/...",
  "requires": [],
  "dependencies": [],
  "hooks": {
    "activate": "init",
    "enable": "onEnable",
    "disable": "onDisable"
  }
}
```

### 4.3 FlyAI 扩展字段

```json
{
  "flyai": {
    "host_api": 1,
    "compat": "logic",
    "capabilities": [
      "chat.read",
      "chat.write",
      "variables.read",
      "variables.write",
      "worldbook.read",
      "generate.quiet",
      "slash.register",
      "settings"
    ],
    "network": {
      "allowed_hosts": ["api.example.com"]
    },
    "panel": {
      "type": "schema",
      "schema": "panel.schema.json"
    }
  }
}
```

### 4.4 校验规则

- `display_name`、`js` 必填；`js` 必须是包内相对路径，禁止 `..`、绝对路径、协议前缀；
- `version` 解析失败则拒绝安装；
- `dependencies` 必须已安装且启用，否则加载时明确报错；
- `loading_order` 缺省 100；
- 单包限制：文件数 ≤ 500，总解压后 ≤ 20MB，单文件 ≤ 5MB；
- 禁止符号链接、设备文件、可执行位；
- 禁止服务端代码（`.py`、`.sh`、`.exe` 等只作为静态文件存在，不执行）；
- manifest 中所有字符串做长度限制与 HTML 转义展示。

### 4.5 安装来源

| 来源 | 首期 | 说明 |
|---|---|---|
| zip 上传 | ✅ | 管理后台上传，服务端校验 |
| Git URL | ⏸ | 需要出站网络、仓库域名白名单、浅克隆、超时/大小限制；放到第二阶段 |
| 市场 | ⏸ | 现有 `MarketEntry.KINDS` 只有 character/world/preset/session；新增 `extension` 类型需单独评审 |

## 5. 后端设计

### 5.1 新模块

```text
flyai/extensions/
  __init__.py
  models.py        # ExtensionManifest, InstallRecord, CompatReport
  store.py         # registry.json / installed/<name> / 用户状态，原子写
  manifest.py      # 解析、校验、默认值
  installer.py     # zip 安全解压、路径校验、sha256、静态扫描
  scanner.py       # import 扫描、模块/符号缺口报告
  service.py       # 安装/更新/删除/启停/设置/装配运行快照
```

### 5.2 存储实现要点

- 所有外部 id 走 `flyai/ids.py` 的 `check_safe_name` / `safe_child`；
- 注册表写入用临时文件 + `os.replace` 原子替换；
- 用户状态按 `data/{uid}/extensions/state.json`，上限 1MB；
- 扩展设置与卡内 `chatMetadata` 隔离，不共享命名空间；
- 安装失败要回滚：先解压到临时目录，校验通过后再原子移动到 `installed/<name>`；
- 卸载只删 `installed/<name>`，注册表标记删除；用户状态中的设置可保留或在确认后清理。

### 5.3 API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/extensions` | 登录 | 列表：manifest 摘要、版本、兼容等级、当前用户是否启用、错误 |
| GET | `/api/extensions/{name}` | 登录 | 详情 + 兼容报告 |
| POST | `/api/extensions/install` | admin | multipart zip；返回安装结果 |
| POST | `/api/extensions/{name}/update` | admin | multipart zip；保留用户设置 |
| DELETE | `/api/extensions/{name}` | admin | 卸载；可选清理用户设置 |
| POST | `/api/extensions/{name}/enable` | 登录 | 当前用户启用 |
| POST | `/api/extensions/{name}/disable` | 登录 | 当前用户停用 |
| PUT | `/api/extensions/order` | 登录 | 当前用户加载顺序 |
| GET | `/api/extensions/{name}/settings` | 登录 | 当前用户该扩展设置 |
| PUT | `/api/extensions/{name}/settings` | 登录 | 覆盖保存，限 1MB |
| GET | `/api/extensions/{name}/host-state` | 登录 | boot 快照：manifest、设置、能力、会话摘要 |
| GET | `/scripts/extensions/third-party/{name}/{path}` | 公开 | 静态文件；CORS `*`；只读 |

`host-state` 不返回其他扩展的设置、角色卡私密字段、密钥明文。

### 5.4 静态资源路由

- 路径必须严格匹配 `installed/<name>/files/<path>`；
- `path` 逐段校验，禁止 `..`、反斜杠、控制字符；
- 只返回普通文件；目录请求 404；
- 响应头：
  - `Access-Control-Allow-Origin: *`
  - `Cross-Origin-Resource-Policy: cross-origin`
  - `X-Content-Type-Options: nosniff`
  - `Cache-Control: public, max-age=300`（更新后加版本 query 或 hash）
  - `Content-Security-Policy: default-src 'none'; sandbox`（对 JS 文件无影响，作为兜底）
- MIME 白名单：`.js`、`.mjs`、`.css`、`.json`、`.html`、`.png`、`.jpg`、`.webp`、`.svg`、`.woff2` 等；未知类型按 `application/octet-stream`。

### 5.5 安装流程

```text
上传 zip
  → 大小/文件数校验
  → 安全解压到临时目录（zip-slip / zip-bomb / 符号链接拒绝）
  → 读取 manifest.json，校验必填字段与 flyai 字段
  → 扫描 JS import：
       - 解析出 ST 模块路径 + 符号
       - 对照模块注册表（见第 7 节）
       - 生成 compat-report.json
  → 计算 sha256
  → 原子移动到 installed/<name>
  → 更新 registry.json
  → 返回 {ok, compatLevel, missingModules, missingSymbols}
```

### 5.6 错误与日志

- 安装错误返回 400 + 中文原因；
- 每个扩展保留最近 50 条加载错误（前端也可上报）；
- 不把扩展堆栈原样回传到管理面板以外的用户；
- 运行日志只记事件类型、错误摘要、耗时，不记聊天正文。

### 5.7 配置

在 `flyai/config.py` 新增：

```python
class ExtensionSettings(BaseModel):
    enabled: bool = False                  # 总开关，默认关
    min_level: int = 256                   # 安装/管理权限；256=仅 admin
    user_enable_allowed: bool = True       # 普通用户是否可自行启用已安装扩展
    max_total_bytes: int = 20 * 1024 * 1024
    max_files: int = 500
    max_settings_bytes: int = 1024 * 1024
    network_enabled: bool = False          # 扩展网络代理总开关
    network_min_level: int = 256
    allow_remote_install: bool = False     # Git 直装，二期
```

挂到 `AppConfig`，沿用 `StNetSettings` 的 `min_level` 校验写法。

### 6.2 管理 UI

位置：设置对话框新增“扩展”页；管理员可见安装/更新/删除，普通用户只可见启用/设置。

组件：

- `ExtensionManagerPanel.tsx`：列表、状态、兼容等级、启停、顺序；

### 6.3 宿主 iframe 生成

`hostDoc.ts` 负责生成 `srcdoc`，顺序：

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <meta http-equiv="Content-Security-Policy" content="...">
  <link rel="stylesheet" href="/scripts/extensions/third-party/<name>/<css>">
  <style>/* 最小基础样式，不复制 ST */</style>
</head>
<body>
  <div id="flyai-ext-root"></div>
  <script>/* stCore */</script>
  <script>/* stNative 快照 + 模块 shim */</script>
  <script>/* 扩展宿主 shim：settings/events/popup/slash/fetch */</script>
  <script type="importmap">{"imports": { ... }}</script>
  <script type="module">
    window.__FLYAI_EXT_BOOT__ = ...;
    import('/scripts/extensions/third-party/<name>/index.js');
  </script>
</body>
</html>
```

CSP 建议：

```text
default-src 'none';
script-src 'unsafe-inline' 'unsafe-eval' data: blob:
            https://<app-origin> <现有 CDN 白名单>;
style-src 'unsafe-inline' https://<app-origin> <现有 CDN 白名单>;
img-src data: blob: https://<app-origin> <现有 CDN 白名单>;
font-src data: https://<app-origin> <现有 CDN 白名单>;
connect-src 'none';
frame-src 'none';
worker-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
```

- 扩展模板/资源由 shim 负责，必要时只对 `<app-origin>/scripts/extensions/` 放行 `connect-src`；
- 不允许扩展加载任意远程脚本；
- 入口 URL 用绝对路径，避免 `srcdoc` baseURL 造成相对解析错误。

### 6.4 postMessage 协议

消息统一：

```ts
type ExtMessage = {
  v: 1
  ns: 'flyai-ext'
  id: string
  type: 'boot' | 'ready' | 'rpc' | 'rpc-result' | 'event' | 'log' | 'error'
  method?: string
  params?: unknown
  result?: unknown
  error?: { code: string; message: string }
}
```

父页面校验：

- `event.source === iframe.contentWindow`；
- `ns === 'flyai-ext'`；
- `id` 长度 / 类型；
- 单条消息序列化后 ≤ 256KB；
- 方法在能力白名单内；
- 每个 RPC 5–30 秒超时；
- 同一扩展并发 RPC ≤ 4。

RPC 方法：

| 方法 | 能力 | 说明 |
|---|---|---|
| `chat.getMessages` | `chat.read` | 返回 ST 形状消息（可限范围） |
| `chat.setMessages` | `chat.write` | 落库，复用 `/st/messages` |
| `chat.addMessage` | `chat.write` | 新增楼层 |
| `chat.deleteMessages` | `chat.write` | 删除楼层 |
| `variables.get` / `variables.set` | `variables.*` | 聊天/全局/消息变量 |
| `worldbook.list` / `get` / `edit` | `worldbook.*` | 复用现有世界书路由 |
| `generate.quiet` | `generate.quiet` | 静默生成，不落用户楼层 |
| `generate.raw` | `generate.raw` | 原始生成 |
| `prompt.setExtension` | `prompt.inject` | 扩展提示词注入 |
| `settings.get` / `settings.save` | `settings` | 按扩展命名空间持久化 |
| `storage.get` / `storage.set` | `storage` | 账号级 KV，可选 |
| `net.fetch` | `net` | 走 `/api/st/net-proxy` |
| `slash.register` | `slash.register` | 注册命令到宿主 |
| `slash.execute` | `slash.execute` | 执行命令链 |
| `ui.toast` / `ui.popup` | `ui` | 宿主原生 toast/弹窗，不暴露 ST DOM |
| `log` | 默认 | 写扩展日志 |

### 6.5 宿主管理器生命周期

1. 聊天页挂载时读取已启用扩展 + 顺序；
2. 对每个扩展创建 iframe，发送 `boot`（manifest、快照、设置、能力、会话摘要）；
3. 等待 `ready`；超时 10 秒标记失败；
4. 监听宿主事件，转发 `event`；
5. 聊天切换/会话切换：重建宿主（或发送 `rebind`，首期重建最简单）；
6. 页面卸载/扩展停用：销毁 iframe、清定时器、撤销 RPC；
7. 错误：记录到 store，管理面板可见。

## 7. 运行时实现

### 7.1 模块注册表

把 `stNative.ts` 里的 `NATIVE_MODULES` 抽成可扩展注册表：

```ts
type StModuleDef = {
  path: string                 // 'script.js' | 'scripts/utils.js' | ...
  source: string | (() => string)
  exports: string[]            // 供安装扫描/诊断使用
  phase: 'P0' | 'P1' | 'P2'
}
```

新增模块时同时更新：

- `NATIVE_MODULES`；
- `exports` 清单（用于兼容报告）；
- `docs/酒馆插件模块与符号覆盖矩阵.md` 的统计（可由脚本生成）。

**导出必须真实存在**：ES module 不能靠 Proxy 兜住未知命名导入。未实现的符号要显式生成导出：

```js
// 生成式桩：名字存在，调用时抛出可诊断错误
export function listTags() {
  throw new Error('ST host interface not implemented: scripts/tags.js.listTags');
}
```

安装扫描时对照清单，提前告诉用户“这个扩展 import 了 3 个未实现符号”，而不是等运行时白屏。

### 7.2 shim 分层

| 层 | 内容 | 复用 |
|---|---|---|
| A | `stCore`：消息形状、变量、世界书、事件常量 | 现有 `compat/stCore.js` |
| B | ST 模块：20 个现有 + 新增模块 | `stNative.ts` |
| C | 全局：`SillyTavern.getContext`、`eventSource`、`extension_settings`、`Popup`、`toastr`、`uuidv4` 等 | 扩展 `authorRuntime` 的 shim |
| D | 宿主桥：fetch/XHR、settings、slash、net、generate | 新写 `extensions/runtime` |
| E | 面板协议（L2） | 新写 |

安全注：`getRequestHeaders()` 只返回内容类型等无凭据头部，**不返回 Bearer / Cookie / CSRF 令牌**；需要鉴权的请求一律走宿主 RPC。

### 7.4 事件总线

实现 ST 兼容的 `eventSource`：

```js
on(event, handler) -> { stop() }   // ST 扩展常见用法
once(event, handler)
off(event, handler)
emit(event, ...args) -> Promise
emitAndWait(event, ...args) -> Promise
removeListener(event, handler)
clearEvent(event)
clearListener(event)
clearAll()
```

- `event_types` 从 `script.js` 与 `scripts/events.js` 同时导出，值必须与 ST 一致；
- `eventMakeFirst` / `eventMakeLast` 用优先级队列实现真实插队；
- 宿主 → 扩展事件：`MESSAGE_SENT`、`MESSAGE_RECEIVED`、`MESSAGE_EDITED`、`MESSAGE_DELETED`、`GENERATION_STARTED`、`GENERATION_ENDED`、`GENERATION_STOPPED`、`CHAT_CHANGED`、`EXTENSIONS_FIRST_LOAD`、`SETTINGS_LOADED`；
- 扩展 `emit` 默认只在本 iframe 内派发；需要影响宿主的（如 `MESSAGE_SENT`）通过 RPC 转发，能力校验后执行，避免循环。

### 7.5 slash 子系统

首期目标不是完整 STscript，而是“能注册、能解析、能执行简单命令”：

1. `SlashCommandParser.addCommandObject(command)` 注册；
2. `SlashCommand.fromProps({ name, callback, argumentList, namedArgumentList, helpString, returns })`；
3. `SlashCommandArgument.fromProps` / `SlashCommandNamedArgument.fromProps`；
4. 解析 `command arg1 arg2 key=value`，支持引号、`|` 管道、`\/` 转义；
5. 执行链把上一段返回值作为 `{{pipe}}`；
6. `SlashCommandScope` 支持局部/全局变量；
7. `SlashCommandAbortController` 支持 `/stop`；
8. 不支持 `if/while/closure` 的高级语法时，明确报 `unsupported`，不静默吞掉。

宿主侧：

- 扩展注册的命令进入全局命令表；
- 用户输入以 `/` 开头时，优先走扩展命令表；
- 没有匹配命令时保持现有行为，不误伤普通文本；
- 命令执行受能力与速率限制。

### 7.6 设置持久化

- `extension_settings` 从 `/api/extensions/{name}/settings` 加载，形状保持 ST 的全局对象：

```js
window.extension_settings = {
  "my-ext": { ... },
  "other-ext": { ... }
}
```

- `saveSettingsDebounced()` 在宿主 iframe 内防抖 500ms，发送 `settings.save`；
- 父页面按扩展名拆分保存，避免一个扩展覆盖另一个；
- 服务端只接受该扩展自己的键，值必须是 JSON，序列化后 ≤ 1MB；
- 更新扩展时保留设置；卸载时询问是否清理；
- 设置读取失败时用 `{}` 并提示，不阻塞扩展加载。

### 7.7 网络与密钥

网络：

- 扩展内 `fetch` 默认被 shim 拦截；
- `net.fetch` → 父页面 → `/api/st/net-proxy`；
- 域名策略 = 全局 `st_net` 配置 ∩ manifest `allowed_hosts`（manifest 为空则只允许全局白名单）；
- 用户必须显式开启 `st_net_proxy_enabled`；
- 请求头只允许 `Accept` / `Content-Type`，Cookie/Authorization 一律丢弃；
- 响应体按 `st_net.max_bytes` 截断；
- 审计日志只记 host/method/status/字节数/耗时。

密钥：

- 首期不支持扩展读取密钥；
- `secret_state` 只返回 `{ configured: true/false }`；
- 如果扩展确实需要第三方密钥，二期做“宿主绑定”：用户在 FlyAI 设置里填密钥，服务端加密存储，代理请求时由宿主机注入，扩展永远拿不到明文；
- 禁止把密钥写进 `extension_settings`。

### 7.8 生成

- `generateQuietPrompt` / `generateRaw` → 父页面 → 现有 `/api/chat` 的 `quiet_prompt` 或作者生成桥；
- 首期非流式，返回完整文本；`stream:true` 时合成 SSE，与现有作者运行时一致；
- 每次生成受用户模型、token 上限、速率限制约束；
- 生成不产生用户楼层（除非扩展显式 `chat.addMessage`）；
- 错误返回结构化 `{ code, message }`，不把服务端堆栈暴露给扩展。

## 9. L2 面板方案（可选）

不做 ST DOM 仿真，提供两种面板形态：

1. **schema 面板**：manifest `flyai.panel.schema` 指向 JSON Schema，FlyAI 用原生表单渲染（文本/数字/布尔/枚举/多行/文件）；
2. **独立面板 iframe**：扩展提供 `panel.html`，在扩展宿主 iframe 内渲染，通过 `settings.get/save` 读写设置；父页面只提供容器和标题。

这样扩展可以有自己的设置 UI，但不需要 ST 的 `#extensions_settings`、jQuery、Popper、ST CSS。

## 12. 风险与回滚

| 风险 | 影响 | 处理 |
|---|---|---|
| ES module 链接失败 | 扩展完全不执行 | 安装扫描 + P0 符号优先 + 诊断桩 |
| 扩展依赖 ST DOM | L1 无法覆盖 | 明确标记 L2/L3，不做无边界兼容 |
| CSP/跨源加载在旧 WebView 失效 | 扩展无法启动 | M0 spike 覆盖 APK WebView；失败则回退方案 B 打包 |
| 扩展供应链风险 | 远程代码、数据外泄 | admin 安装、zip 校验、能力声明、网络代理、无密钥明文 |
| 恶意 postMessage | 越权调用宿主 | source/ns/能力/大小/超时校验 |
| 扩展设置无限增长 | 存储/性能 | 1MB 限制、按扩展隔离、拒绝非 JSON |
| 扩展卡死/死循环 | 聊天页卡顿 | iframe 隔离、RPC 超时、宿主侧速率限制；必要时“停用扩展” |
| ST 版本演进 | 模块/符号漂移 | 兼容矩阵 + 契约测试 + 版本化 host_api |
| 许可证/分发 | 法务风险 | 安装时展示来源与许可证；不内置第三方扩展 |
| 与卡运行时冲突 | 现有功能回归 | 独立宿主、独立 feature flag、回归测试 |

回滚开关：

- `config.extensions.enabled = false`：全局关闭，管理入口隐藏，宿主不挂载；
- 用户级 `extensions_enabled`：单用户关闭；
- 单扩展停用：不动其他扩展；
- 删除 `installed/<name>` 不影响卡运行时；
- 数据备份：`registry.json` 与用户状态可手工恢复。

## 14. 验收标准

### 14.1 M1 验收

- 管理员上传 zip，安装成功/失败都有明确原因；
- 安装后出现在列表，可启停、卸载；
- 普通用户看不到安装入口，只能启用/设置；
- 恶意 zip（zip-slip、超限、非法 manifest）全部被拒；
- 静态路由不能穿越到扩展目录之外。

### 14.2 M2 验收

- 5 个 fixture 扩展全部通过；
- `eventSource` 返回 `{ stop }`，`emitAndWait` 等待异步监听器；
- `extension_settings` 刷新后保留；
- `generateQuietPrompt` 返回文本，不产生用户楼层；
- 扩展无法直接访问父页面、Cookie、localStorage、外网；
- 卡内运行时现有测试全绿。

### 14.3 M3 验收

- 至少 5 个真实逻辑型扩展可用，兼容矩阵记录缺口；
- slash 命令可注册/执行/返回管道值；
- 未实现符号报明确错误，不白屏；
- 管理面板能看到每个扩展的缺失模块/符号。

### 14.4 性能与移动端

- 扩展宿主启动不影响聊天首屏；
- 10 个扩展同时启用的内存/CPU 有基线；
- APK WebView 下安装、启用、运行、卸载全流程通过；
- 扩展错误不阻塞其他扩展与聊天。

## 15. 建议的首批扩展样本

优先选“逻辑型、无 ST DOM、依赖模块少”的扩展做适配，验证路径后再扩展：

1. 只监听事件 + 改变量（如自动总结、计数器）；
2. 只注册 slash 命令 + 读写变量；
3. 调用静默生成 + 注入提示词；
4. 读写世界书条目；
5. 带简单设置面板（用 L2 schema 面板）。

每类选 1–2 个，形成 `tests/fixtures/extensions/` 与兼容矩阵的第一批数据。

---

## 16. 实施顺序建议（一句话版）

**先做 M0 spike 证明“多文件扩展能在 opaque-origin iframe 里按 ST 路径加载”，再做 M1 管理器，再按覆盖矩阵补 P0 符号，最后用 fixture + 真实扩展迭代；UI 型扩展始终不承诺。**
