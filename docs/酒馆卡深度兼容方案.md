# 酒馆卡深度兼容方案（1–5）

目标：把《红楼风月录》《约会大作战P-v1》从“能打开”推进到“主流程可用”，并为通用酒馆卡建立一套可持续的兼容层。

不在本期范围（按 `docs/酒馆助手全量API语义对照.md` 的标记）：

- audio、extension、file、import_raw、script
- ST 扩展执行、tokenizer、secrets、vector/translate/search
- ST 各家模型通道（FlyAI 使用自己的 provider）

---

## 0. 现状与根因

1. **两个运行时**
   - `webapp/src/services/st/cardApp.ts`：消息 HTML iframe，开场页/选项/手机/终端。
   - `webapp/src/services/st/authorRuntime.ts`：状态面板/手札 iframe。
   - 两套 API 面不一致：`cardApp` 没有 `updateChatMetadata`、`saveMetadata`、`injectPrompts`、`generateRaw`、`setChatMessages`、`deleteChatMessages`，`chatMetadata` 还是硬编码 `{}`。
2. **同名不同语义**
   - `setChatMessages` 只改 iframe 镜像，不落库。
   - `context.generate` 走静默桥/`generateFromComposer`，不产生主聊天楼层。
   - `chatMetadata` 不持久化。
3. **ST 服务端依赖**
   - `/api/chats/get`、`/api/users/me`、`/api/files/sanitize-filename`、`accountStorage`。
   - `/api/worldinfo/*` 写回依赖 `/api/sessions/{sid}/st/world`，未绑定世界书时 400。
4. **提示词内核不同**
   - FlyAI 的 `LoreEntry` 只保留 `title/content/pinned/keys/position/depth/order/role/probability`，丢弃 `enabled/constant/selective/scanDepth/递归/冷却` 等字段。
   - 约会大作战用 `enabled` 控制剧情线；红楼用时线条目。只存数据不改变 prompt，模型行为不会变。
5. **UI/生命周期**
   - 消息 iframe 随楼层更新重建；`localStorage` 是内存实现；手札舆图/手机都是嵌套 iframe，跨域桥未完成。

---

## 1. 共享兼容层

### 目标

让 `cardApp` 和 `authorRuntime` 共用同一套 TavernHelper API 实现，避免两套 shim 继续分叉。

### 设计

新增 `webapp/src/services/st/compat/`：

```
compat/
  types.ts          # 共享类型：ChatMessage, WorldbookEntry, InjectionPrompt...
  core.ts           # 纯函数：消息范围解析、变量合并、世界书数组转换
  runtime.ts        # createStRuntime(host) → { TavernHelper, globals, context }
  hosts/
    cardAppHost.ts  # cardApp 的能力实现（消息 HTML）
    authorHost.ts   # authorRuntime 的能力实现（状态面板）
```

`host` 接口：

```ts
type StHost = {
  sessionId: string
  chatId: string
  userName: string
  character: { name?: string; avatar?: string; description?: string }
  messages: AuthorRuntimeMessage[]
  variables?: Record<string, unknown>
  chatMetadata?: Record<string, unknown>
  canWrite: boolean
  canAct: boolean
  emit(event: string, ...args: unknown[]): void
  post(msg: unknown): void
  request(path: string, init?: RequestInit): Promise<Response>
  storage: { get(key: string): string | null; set(key: string, value: string): void }
}
```

实现原则：

- API 只写一次；两个 host 只实现“取数据/发消息/发请求”。
- 能力不足时返回明确的 `Error('flyai-unsupported: ...')`，不再静默返回空值。
- 所有 API 同时挂到 `window.X` 和 `TavernHelper.X`，两边一致。
- 先迁移只读 API，再迁移写 API，最后迁移 generate/events。

### 验收

- 两个 iframe 内 `Object.keys(TavernHelper)` 一致。
- 同一套 `compat/runtime.test.ts` 对两个 host 各跑一遍。
- 卡里 `createChatMessages(...)` 与 `TavernHelper.createChatMessages(...)` 行为一致。

## 2. 宿主桥

### 2.1 chatMetadata

新增协议：

- `ST_MSG_METADATA_GET`
- `ST_MSG_METADATA_SET` / `ST_MSG_METADATA_RESULT`

后端：

- `GET /api/sessions/{sid}/st/chat-metadata`
- `POST /api/sessions/{sid}/st/chat-metadata`（上限 1MB）

存储：`session.attributes.author.chat_metadata`（已有字段，直接复用）。

### 2.2 消息写回

新增协议：

- `ST_MSG_MESSAGES_PATCH`：`{ changes: [{message_id, message?, data?, is_hidden?, swipes?, swipe_id?}], refresh }`
- `ST_MSG_MESSAGES_CREATE`
- `ST_MSG_MESSAGES_DELETE`
- `ST_MSG_MESSAGES_RESULT`

后端：

- `PATCH /api/sessions/{sid}/st/messages`
- `POST /api/sessions/{sid}/st/messages`
- `DELETE /api/sessions/{sid}/st/messages`

要求：

- 写入真实 `Session.messages`/thread messages，而不是 iframe 镜像。
- 写完后由前端刷新消息列表；卡内收到 `MESSAGE_UPDATED`。
- 下一次生成必须能看到修改后的消息。

### 2.3 主聊天生成

新增协议：

- `ST_MSG_GENERATE_MAIN`：`{ type, options }`
- `ST_MSG_GENERATE_MAIN_RESULT`

后端：

- `POST /api/sessions/{sid}/st/generate`
- 支持 `quiet_prompt`、`automatic_trigger`、`max_chat_history`。
- 实现方式：把 `quiet_prompt` 作为临时 system/深度注入，走现有 `/api/chat` run，结果写入助手楼层。

前端：

- 复用 `sendCardMessage`/`continueReply` 的 run 管理，但不要产生可见 user 消息。
- 生成结束派发 `MESSAGE_RECEIVED`、`GENERATION_ENDED`。

### 2.4 世界书写回

- `saveWorldbook` 保留现有 `ST_MSG_WRITE_WORLD`。
- 后端 `/api/sessions/{sid}/st/world`：
  - `world_override` 不存在时，从角色卡 `table`/`extensions.world` 派生一份，而不是 400。
  - 写回时保留 ST 字段（`enabled/constant/selective/keysecondary/scanDepth/...`），不要被 `LoreEntry.from_dict` 丢掉。
- `updateWorldbookWith` 只在内容变化时写回，避免只读回调触发 400。

### 2.5 存储桥

- `localStorage` / `sessionStorage` / `accountStorage` 统一走宿主：
  - `ST_MSG_STORAGE_GET`
  - `ST_MSG_STORAGE_SET`
- 存储位置：
  - 会话级：`session.attributes.storage`
  - 用户级：`user_settings.storage`
- 键名加卡/会话前缀，避免串卡。

### 验收

- 刷新后手札/手机设置仍在。
- `setChatMessages` 修改正文后，下一次生成使用新正文。
- `context.generate('normal', {quiet_prompt})` 产生助手楼层。
- 未绑定世界书的会话写世界书不再 400。

## 3. ST-compat 路由 + fetch 桥

### 3.1 命名空间

后端新增 `/api/st-compat/*`，不直接占用 ST 原路径，避免和 FlyAI 现有路由/鉴权冲突。

前端 `window.fetch` 拦截：

```
ST 路径表 → 命中 → postMessage CARD_MSG_FETCH / AUTHOR_MSG_FETCH
        → 宿主调用 /api/st-compat/...
        → 转回 ST 形状
```

绝不把 Bearer token 暴露给 iframe。

### 3.2 P0 路由

| ST 路径 | FlyAI 实现 | 说明 |
|---|---|---|
| `/api/worldinfo/get` | `GET /api/st-compat/worldinfo/get` | 会话世界书/角色 worldbook |
| `/api/worldinfo/edit` | `POST /api/st-compat/worldinfo/edit` | 写 world_override |
| `/api/worldinfo/delete` | `POST /api/st-compat/worldinfo/delete` | 清空/删除 |
| `/api/worldinfo/list` | `GET /api/st-compat/worldinfo/list` | 列表 |
| `/api/worldinfo/import` | `POST /api/st-compat/worldinfo/import` | 导入 |
| `/api/chats/get` | `GET /api/st-compat/chats/get` | 会话消息/元数据 |
| `/api/chats/save` | `POST /api/st-compat/chats/save` | 写消息/元数据 |
| `/api/chats/rename` | `POST /api/st-compat/chats/rename` | 会话标题 |
| `/api/chats/delete` | `POST /api/st-compat/chats/delete` | 删除会话 |
| `/api/users/me` | `GET /api/st-compat/users/me` | 映射 `/api/auth/me` |
| `/api/files/sanitize-filename` | `POST /api/st-compat/files/sanitize-filename` | 复用宿主文件名规则 |
| `/api/backends/chat-completions/generate` | `POST /api/st-compat/backends/chat-completions/generate` | 走主聊天生成/静默生成 |
| `/api/backends/chat-completions/status` | `GET /api/st-compat/backends/chat-completions/status` | 映射模型列表 |

### 3.3 P1 路由

- `/api/characters/*`：create/edit/get/all/import/export/duplicate/rename。
- `/api/presets/save|restore|delete`。
- `/api/avatars/upload|get|delete`。
- `/api/assets/*`、`/api/images/*`、`/api/backgrounds/*`。
- `/api/groups/*` → rooms。
- `/api/settings/get|save`。
- `/api/speech/*`、`/api/stats/*`。

### 3.4 错误/形状适配

- ST 返回 `{ error: { message } }`；FastAPI 返回 `{ detail }`。
- 统一适配：
  - `chat` 消息补齐 `name/role/is_hidden/message/data/extra/swipes`。
  - worldbook 条目补齐 ST 字段。
  - character 补齐 `first_messages/extensions/worldbook/creator_notes`。

### 验收

- 约会大作战手机保存后 `/api/chats/get` 回读成功。
- 账号 handle 可读取。
- 聊天改名通过。
- 红楼/约会大作战的 worldinfo 读写走同一套。

## 4. 提示词语义

### 4.1 扩展世界书模型

`flyai/lore/models.py` 的 `LoreEntry` 增加：

```python
enabled: bool = True
constant: bool = False
selective: bool = True
secondary_keys: List[str] = []
selective_logic: str = "and_any"   # and_any/and_all/not_all/not_any
scan_depth: Optional[int] = None   # None=same_as_global
case_sensitive: bool = False
match_whole_words: bool = False
exclude_recursion: bool = False
prevent_recursion: bool = False
delay_until_recursion: Optional[int] = None
sticky: Optional[int] = None
cooldown: Optional[int] = None
delay: Optional[int] = None
group: str = ""
group_weight: int = 100
position_type: str = "at_depth"     # before/after char、before/after examples、before/after AN、at_depth
```

`from_dict/to_dict` 全部保留，不能丢字段。

### 4.2 扩展 LoreQuerier

- `enabled=False` 永不注入。
- `constant=True` 无条件注入。
- `selective=True` 按主/次关键词、逻辑、扫描深度匹配。
- 支持 `sticky/cooldown/delay`（按楼层计数）。
- 支持 `position_type`：
  - before/after character definition
  - before/after example messages
  - before/after author note
  - at_depth
- 保持现有 `pinned/probability` 兼容。

### 4.3 预设/正则顺序

- 预设块按 ST 的 `prompt_order`/`position` 排序。
- prompt 侧正则先于世界书注入/宏替换执行；display 侧仍走现有 regex。
- 提供“prompt 快照”测试：固定会话 + 固定变量，比较 ST/FlyAI 的注入顺序和内容。

### 验收

- 约会大作战关闭某条剧情 UID 后，prompt 中不再出现该条目。
- 红楼时线条目能按 `enabled/keys/scanDepth` 激活。
- 预设顺序与卡预期一致，模型回复不再“像换了一张卡”。

## 5. UI / 生命周期

### 5.1 消息 iframe

- 以 `messageId + revision` 作为 iframe key；变量/状态更新走 postMessage，不重建。
- 楼层重新渲染后重放 `READY`、变量、chat、metadata、事件。
- 卡内滚动位置、折叠状态、表单草稿写入宿主存储桥。

### 5.2 嵌套 iframe

- 手札舆图：
  - 由宿主渲染 map 组件，或把 map iframe 的消息经 shell 转发到作者帧。
  - 保留 `HLMMapRuntime` 的 `attach/detach/html` 接口。
- 约会大作战手机/终端：
  - 增加 `accountStorage`、`chats/get`、`files/sanitize-filename`、图片 fetch 桥。
  - 明确能力白名单：不支持的 DOM/命令返回结构化错误，而不是静默失败。

### 5.3 安全

- iframe 继续 `sandbox` 无 `allow-same-origin`。
- 所有网络经宿主桥，CSP 保持 `connect-src 'none'`。
- 外部图片走 `img-proxy`，外部请求走 `net-proxy`（按现有 SSRF 防护）。
- 不把 Bearer token、Cookie、账号信息透传给卡。

### 验收

- 刷新页面后手札/手机状态恢复。
- 舆图可打开、可保存标注。
- 手机设置、照片策略刷新不丢。
- 无 cross-origin / CSP 报错。

| 阶段 | 相对工作量 | 依赖 | 说明 |
|---|---|---|---|
| 0 共享层 | M | 无 | 先做，否则后面每项都要写两遍 |
| 1 Batch A + 宿主桥 | M | 阶段 0 | 直接决定两张卡主流程 |
| 2 ST-compat P0 | M | 阶段 1 | 约会大作战必需 |
| 3 提示词内核 | L | 阶段 2 | 决定模型行为是否真的像酒馆 |
| 4 UI/嵌套 iframe | M | 阶段 1/2 | 手札舆图、手机、刷新恢复 |
| 5 通用卡扩展 | L | 阶段 0–3 | 按卡的实际使用逐步补 |

建议先做 **阶段 0 + 1**，用两张卡做验收；通过后再进入 2/3。阶段 5 不应一次性铺开，按真实卡的缺口追加。

## 风险与取舍

- **两套 shim 继续分叉**：阶段 0 必须完成，否则后续每补一个 API 都要写两遍。
- **提示词行为变化**：世界书/预设/正则改动会影响所有卡，需要快照测试和按用户开关灰度。
- **数据迁移**：`LoreEntry` 新增字段要兼容旧数据，缺失字段用默认值。
- **安全**：ST-compat 路由只走宿主桥，禁止把 token 暴露给 iframe。
- **性能**：消息写回和 metadata 保存要防抖；大世界书不要每次全量序列化。
