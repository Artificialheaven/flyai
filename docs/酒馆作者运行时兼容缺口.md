# 酒馆作者运行时兼容缺口

记录时间：2026-11-22  
对应版本：FlyAI 1.44.6146  
验证会话：《红楼风月录》黛玉开局设定

本轮已修复：脚本逐文件独立作用域、Zod 注册递归、酒馆事件/脚本按钮、chatMetadata 持久化、手札 shell postMessage RPC、`generateRaw` / `stopGenerationById`。

## 未完成项

### 1. `setChatMessages` / `setChatMessage`

- **现状**：作者运行时没有这两个全局函数。
- **影响**：`hlm-storage-dedupe-v1` 开头检测到 `setChatMessages !== 'function'` 直接 return，TavernDB 的重复配置键、内部表指南不会清理。不会立即报错，但长局 message 0 的变量会持续膨胀。
- **建议**：增加「按消息写回变量」的宿主桥（前端 postMessage + 后端会话写入），先支持 `message_id + variables` 的最小集合，再补 `refresh` 选项。

### 2. `injectPrompts` 的 `filter` 函数

- **现状**：prompt 对象经 `clone` / postMessage 后只剩文本，`filter` 函数被丢弃。
- **影响**：手札的剧情约束 `filter: () => alive && normalActive && ...` 退化为无条件注入；角色死亡、助手任务进行中或切换聊天后仍会继续注入。
- **建议**：iframe 内保留 filter 闭包与 id，宿主组装提示词时回调 iframe 求值；或改为每次变量/消息更新时在 iframe 内重新计算并推送最终文本。

### 3. 手札「舆图」

- **现状**：手札 shell 的 `HLMHandbookAdapter` 已通过 RPC 桥接；`HLMMapRuntime` 仍不可用，点「舆图」提示「舆图组件尚未就绪」。
- **原因**：map iframe 嵌在 shell 内，跨域无法把 frame 节点交给作者帧的 map runtime，消息通道也未转发。
- **建议**：在 shell 内代理 map iframe 的 `hlm-map-editor-v1` 消息到作者帧，再把响应转发回去；或把舆图改为宿主层组件。

### 4. `localStorage` 偏好

- **现状**：作者 iframe 是无同源权限的 opaque origin，`localStorage` 访问抛异常。
- **影响**：纸面主题 `PAPER_KEY` 读取失败后按 `true` 处理，功能默认开启；用户开关刷新后丢失。主题、头像等本地设置同样不保留。
- **建议**：增加宿主 storage 桥（按会话/卡隔离的键值存储），或在 `chatMetadata` 下开一个命名空间。

### 5. `context.saveChat()`

- **现状**：空实现，返回 resolved Promise。
- **影响**：轻量投影脚本的清理结果不回写；MVU 变量写入本身已持久化，影响有限。
- **建议**：接入现有会话保存接口，或明确返回 `false` 让脚本走降级路径。

## 次要限制

- `getChatWorldbookName()` 返回 `null`；卡会回退到 `getCharWorldbookNames('current')`，当前不受影响。
- `getPresetNames()` 返回空数组、`getPresetManager()` 返回 `null`，手机预设选择不可用。
- 手札独立生成忽略卡内 `custom_api.endpoint/key`，统一走会话模型并在宿主确认；这是有意的安全取舍。
- `eventMakeFirst` / `eventMakeLast` 目前与普通注册同序，未实现真正的插队语义。
