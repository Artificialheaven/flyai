# 酒馆插件模块与符号覆盖矩阵

- 统计时间：2026-11-24
- 上游基准：`SillyTavern-release` 1.19.1 `public/`
- 统计对象：`public/scripts/extensions/` 下所有内置扩展（14 个扩展目录）的 `import { ... } from '...'`
- 本地实现：`webapp/src/services/st/native/stNative.ts` 的 `NATIVE_MODULES`
- 方法：静态扫描 `import` 语句，按解析后的模块路径和符号名去重；同一符号被多个扩展引用只计一次
- 说明：本文只做覆盖事实统计与定义说明，不含实施方案；实施方案见 `docs/酒馆插件兼容施工方案.md`

---

## 0. 口径

### 0.1 为什么以“内置扩展”为样本

内置扩展覆盖了 ST 扩展最常见的用法：设置面板、slash 命令、世界书、生成、附件、TTS、翻译、向量、图片。它们比单个第三方扩展更全面，也比“任意扩展”更可枚举。第三方扩展只会在此之外增加更多依赖，不会减少。

### 0.2 统计结果总览

| 指标 | 数量 |
|---|---:|
| 扩展 import 的模块路径 | 41 |
| 其中扩展内部模块（不需要宿主提供） | 3（quick-reply 自己，4 个符号） |
| 宿主相关模块 | 38 |
| 宿主相关符号 | 184 |
| 本地已有同名导出的符号 | 33（17.9%） |
| 其中：形状基本可直接用 | 约 19 |
| 其中：已导出但为简化/桩/只读快照 | 约 14 |
| 本地 `NATIVE_MODULES` 模块数 | 20 |
| 与 38 个宿主模块重合 | 11（28.9%） |
| 完全缺失的宿主模块 | 27 |

### 0.3 状态图例

| 标记 | 含义 |
|---|---|
| ✅ | 本地同名导出，形状基本可用 |
| 🟡 | 本地同名导出，但为简化实现、只读快照或空桩 |
| ❌ | 本地模块存在，但没有该导出（`import` 会链接期失败） |
| ⛔ | 本地模块整体不存在（等价于该符号不可用） |
| N/A | 扩展内部模块，不需要宿主实现 |

> **关键事实**：ES module 的命名导入在模块链接期解析。一个扩展只要 `import { X } from '.../script.js'`，而本地 `script.js` 没有导出 `X`，整个扩展模块图就会加载失败，不是“运行时读到 undefined”。因此符号表中的 ❌ / ⛔ 不是“功能降级”，而是“扩展完全起不来”。

### 1.1 模块层面的结论

- 本地 20 个模块主要服务“卡内脚本”：`script.js`、`world-info.js`、`power-user.js`、`extensions.js`、`openai.js`、`tokenizers.js`、`lib.js` 等都有，但都是**按卡的实际调用面裁剪过的子集**。
- 扩展生态真正高频的 `popup.js`、`slash-commands/*`、`secrets.js`、`constants.js`、`i18n.js`、`RossAscends-mods.js` 全部缺失。
- `lib.js` 是特例：本地有 11 个导出，但扩展需要的 6 个里只命中 `Fuse`、`hljs`，缺 `DOMPurify`、`Popper`、`lodash`、`morphdom`。
- `chats.js`、`world-info.js` 这类“模块在但导入符号 0 命中”的情况最危险：看起来有模块，实际 `import` 仍然会失败。

## 4. 读表结论

1. **模块覆盖不是主要瓶颈，符号覆盖才是**：本地已有 11 个模块与扩展重合，但 128 个被 import 的符号只命中 33 个。
2. **最致命的三个缺口**：
   - `script.js` 没有导出 `eventSource` / `event_types`（扩展普遍从 `script.js` 导入）；
   - `popup.js` 整体缺失；
   - `slash-commands/*` 整体缺失。
3. **“同名不同义”比“没有”更隐蔽**：`extension_settings`、`power_user`、`oai_settings`、`tokenizers` 都有导出，但都是只读快照或空桩，扩展写入不会持久化。
4. **纯函数缺口成本最低**：`utils.js` 缺的 30 个里大部分是纯函数，适合优先补齐，能显著提高逻辑型扩展的启动成功率。
5. **UI 型扩展的缺口集中在 DOM 与 popup**：`appendMediaToMessage`、`updateMessageBlock`、`renderExtensionTemplateAsync`、`Popup`、`DOMPurify`、`Popper`、`morphdom`，这些需要 DOM/UI 适配层，不能靠补数据桩解决。
