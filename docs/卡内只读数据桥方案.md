# 卡内只读数据桥方案

> **状态：设计草案，未实施（2026-11-19；同日补充 L4 授权能力阶梯与卡片联网设计）**  
> **范围：本批次只读展示，不写回会话变量；远期授权能力见 §2.1，卡片联网见 §2.2，父窗口外观见 §2.3，均未实施**  
> **前置条件：用户个人设置开启 JS 沙箱；管理员默认开启，普通用户默认关闭。**  
> **信任模型：卡内代码视为用户自行选择运行的程序，来源是否可信由用户自负；项目负责隔离宿主身份、约束服务器网络位置，不为卡内代码背书。**  
> 本文只描述通用技术能力，不包含卡内叙事正文，也不复制真实 `stat_data` 数值。

## 1. 背景与目标

FlyAI 已支持把酒馆卡中的整页 HTML+JS 应用放进 null-origin 沙箱 iframe 运行，并支持
原生 MVU 的 `stat_data` 计算与会话快照。但两套能力目前没有接上：

- 沙箱 shim 只提供空的 `getVariables()`，没有 `getAllVariables()`、`Mvu`、
  `waitGlobalInitialized`、`errorCatched` 等卡内脚本常用的入口。
- 依赖 `getAllVariables().stat_data` 填值的状态栏脚本会在初始化阶段失败，页面只剩
  空骨架。
- 原生“状态面板”抽屉固定走 `SanitizedHtml`，不执行卡内脚本，因此也无法用脚本
  把变量渲染到自定义 UI 中。

目标是补一条**只读数据桥**：让卡内应用读到当前会话或当前消息的 `stat_data`，完成
首屏渲染与本地交互；所有写入 API 都是只读桩，不修改会话状态。后端 MVU 状态机、
卡源文件、数据库与 API 均不改动。

## 2. 能力阶梯

| 层级 | 范围 | 可以做到 | 不能做到 |
|---|---|---|---|
| **L0 现状** | 不改 | 消息中的卡内 HTML 静态清洗预览 | 不执行 JS；不填数值；按钮无反应 |
| **L1 只读首屏** | 核心 | 卡内应用在沙箱中初始化，读取 `{ stat_data }`，显示数值、进度条、页签、CSS 动画；编辑/删除只弹“只读”提示 | 不写回；不联网抓头像；不替代完整 ST 扩展运行时 |
| **L2 只读实时** | 核心 | 助手回复更新 MVU 后，已打开的面板通过 `postMessage` 刷新，不重载 iframe；原生抽屉可切换“当前 / 某条消息快照”（可作为第二批） | 不修改历史消息快照；不推送流式 token 的中间变量状态 |
| **L3 兼容/离线** | 可选后续 | 本地打包 jQuery；补更多 ST 变量别名；按需读取头像配置；错误角标 | 仍不写回、不发消息、不注入世界书 |
| **L4 授权能力（远期）** | 远期 | 见 §2.1：授权动作、会话副本写入、受控网络（§2.2）、流式变量预览、父窗口外观（§2.3） | 仍不做静默写入、根卡/公共卡写入、同源 `window.parent` 桥、完整 ST 扩展运行时、任意外网直连 |

前提始终是：该用户的 `js_sandbox` 已开启。关闭时仍走 L0 静态清洗路径；本方案不改变
这个安全默认值。

### 2.1 L4 授权能力阶梯（远期）

> 本节全部能力都不属于本批次。逐项实现时必须补齐授权、校验与审计，且不改变
> §4.4 的沙箱默认值。

| 子层 | 能力 | 允许形式 | 硬性约束 |
|---|---|---|---|
| **L4-A 授权动作** | 发送 / 重生成 / 继续 | 卡只发意图，宿主弹窗展示完整参数，用户逐次确认后由宿主调用现有接口 | 一次一确认、拒绝后不重试、每会话频率上限、消息标注来源。发送与重生成已有接口（`POST /api/chat`、`ChatRequest.regenerate_message_id`）；继续需先补服务端字段（`ChatRequest` 现无 continue，前端 `continueReply` 为空实现） |
| **L4-B 副本写入** | 变量写回、世界书/角色写 | 仅写会话副本：`session.character_override`、`session.world_override`、`RoomMember.override`（`fork_character` / `fork_world`、`POST /sessions/{sid}/character/fork`） | 根卡与公共卡永不写；`World` 无 `parent_id`，按“是否存在会话副本”判断，而不是“是不是副卡”；无副本时弹窗提示派生。变量写回必须走消息快照通道（`flyai/st/mvu.py::recompute_state` 会覆盖直写 `session.mvu` 的值），并带 `origin: "card"` 与 patch 大小/深度/路径校验 |
| **L4-C 受控网络** | 脚本发起的 `fetch` / XHR | 见 §2.2：shim 替换网络 API，经 `postMessage` 交给宿主，由 `/api/st/net-proxy` 取回 | CSP 不放宽；SSRF 防护、去凭据、大小/超时/配额、逐跳重定向校验不可关闭；管理员三档策略；用户按卡/按域名授权 |
| **L4-D 流式变量预览** | 生成过程中面板显示中间状态 | 前端本地只解析已闭合的 `<UpdateVariable>` 块，按 RFC 6902 + `delta`/`insert` 应用，节流刷新；终态用服务端权威快照整体覆盖 | 不修改消息快照；中间态标记“预览”；patch 语义与 Python 侧保持一致，防漂移 |
| **仍不做** | — | — | 静默/自动写入、写根卡或公共卡、同源 `window.parent` 桥、完整 ST 扩展运行时、任意外网直连、未经确认的循环自动化 |

关于 L4-C：CORS 只约束“脚本能否读取响应”，不约束“请求是否已经发出”；用户授权
既绕不过 null-origin 的 CORS 限制，也挡不住把数据编码进 URL 或图片请求外带。因此
外网访问只能走受控代理，并把完整 URL（含 query）展示给用户确认，而不是允许卡片直连。
§2.2 的做法是保持 `connect-src 'none'`，把脚本发起的 `fetch`/XHR 交给宿主代理；
图片、脚本、样式、字体不读取响应，继续按原 CSP 直连。

### 2.2 卡片联网（网络桥）

> 不属于本批次，单独一批实施。本节把 §2.1 的 L4-C 展开成可落地的设计；它是
> “卡片即程序”信任模型的直接结果：不判断卡内代码是否安全，只保证卡内代码拿不到
> 宿主身份，也不能把服务器变成探测内网或对外滥用的跳板。

#### 2.2.1 拦截点与分工

CSP 保持不变（`connect-src 'none'`、`default-src 'none'`、脚本/样式/图片白名单原样）。
按“是否读取响应”分工：

| 请求类型 | 走法 | 原因 |
|---|---|---|
| 脚本发起的 `fetch` / `XMLHttpRequest` | shim 替换 → `postMessage` → 宿主 → 服务端代理 | 需要读响应，受 CORS 约束；服务端取回不受 CORS 影响 |
| `<img>`、`<script src>`、样式表、字体、音视频 | 直连，受现有 CSP 白名单与“外链插图”开关约束 | 资源标签不读取响应，CORS 不参与；不消耗服务器带宽 |
| `WebSocket` / `EventSource` | 仍禁止，shim 给出明确错误 | 需要长连接与协议状态，代理无法等价转发 |
| ES module `import` | 直连，仅限 `script-src` 白名单主机 | CORS-mode；需要时按主机逐步加白 |

这样不需要判断“哪个请求会被 CORS 拦”：shim 里的网络 API 就是唯一拦截点，凡是卡内
脚本想读响应，必然经过代理。

#### 2.2.2 消息协议

沿用 §4.2 的来源校验与版本号：

| 方向 | `type` | 载荷 |
|---|---|---|
| iframe → 宿主 | `flyai-card-fetch` | `{ v:1, id, url, method, headers, body?, responseType? }` |
| 宿主 → iframe | `flyai-card-fetch-result` | `{ v:1, id, ok, status, headers, bodyText?, bodyB64?, error? }` |
| iframe → 宿主 | `flyai-card-fetch-abort` | `{ v:1, id }` |

- 宿主按 `id` 关联并设置超时；iframe 只有收到结果才能构造 `Response`。
- shim 同时提供一个最小 `XMLHttpRequest` 适配器（`open/send/status/responseText/onload`），
  保证 jQuery `$.getJSON` 一类调用可用。
- 宿主调用后端时使用**宿主自己的登录凭证**；卡内脚本拿不到 token、Cookie 或
  `localStorage`。

#### 2.2.3 服务端 `POST /api/st/net-proxy`

复用 `/api/st/img-proxy` 的 `netguard.resolve_and_check` + `pin_request`：

| 项 | 规则 |
|---|---|
| 协议 | 只允许 `http` / `https` |
| 目标地址 | 拒绝环回、私有、链路本地、保留地址与云元数据地址，IPv4/IPv6 都按解析结果校验；这同时挡住卡去访问 FlyAI 自身的内网接口 |
| 重定向 | 默认最多 5 跳，每一跳重新解析并校验，禁止跳入内网 |
| 请求头 | 只透传 `Accept`、`Content-Type`；`User-Agent` 固定；丢弃 `Cookie`、`Authorization`、`Referer`、`Origin` |
| 响应 | 不返回 `Set-Cookie`；默认上限 5 MB、15 s 超时；二进制响应以 base64 返回 |
| 配额 | 每用户每分钟请求数与并发上限；超限返回可读错误 |
| 审计 | 记录用户、主机、方法、状态、字节数、耗时；完整 URL（含 query）是否入库由部署配置决定 |

以上限制属于**服务器自身的安全边界**，不随用户授权关闭——用户同意的是“我的卡片可以
联网”，不是“服务器可以被当作代理滥用”。

#### 2.2.4 管理员策略

| 策略 | 行为 |
|---|---|
| `off` | 网络桥关闭，卡内 `fetch` 直接拒绝 |
| `allowlist`（建议默认） | 只代理管理员配置的域名 |
| `any-public-https` | 任意公网 https，仍受 §2.2.3 全部限制 |

#### 2.2.5 用户授权粒度

- **卡级**：首次出现联网请求时提示“此卡请求访问网络”，记录卡哈希与会话，可随时撤销。
- **域名级**：首次访问某域名时展示完整 URL（含 query）与方法，选项为“仅本次 /
  本会话允许此域名 / 拒绝”；同会话内缓存，避免逐张图片弹窗。
- **拒绝或关闭**：shim 的 `fetch` 以 `TypeError` reject，卡内 `try/catch` 正常降级；
  本卡的状态栏已有这种降级路径。
- 图片与媒体不走代理，仍由“外链插图”开关控制。

#### 2.2.6 仍然不行的场景

- 需要登录态的请求（代理不带 Cookie，也不转发浏览器凭证）。
- `WebSocket` / `EventSource` 与流式下载。
- 依赖用户真实 IP、浏览器指纹或来源页防盗链的接口（服务端 IP 与无 `Referer` 可能被 403）。
- 不在 `script-src` 白名单里的 ES module。
- 超过大小/超时上限的响应。

对本示例卡而言：头像配置 JSON 可以经代理读取；`cdn.imgchest.com` / `cb.wss.moe`
的背景图仍走 `img-src`，需要用户开启“外链插图”。

### 2.3 父窗口外观（facade，远期）

> 不属于本批次，也不属于 §2.2。它不建立同源桥，而是利用 `window.parent` /
> `window.top` 的可替换（`[Replaceable]`）语义，在 iframe 内把它们指向一个**本地
> 普通对象**，只提供白名单 API。真实父窗口仍然跨源不可访问。

#### 2.3.1 能解决什么

| 卡内写法 | 现状 | facade 后 |
|---|---|---|
| `window.parent.$` / `parent.jQuery` | 跨源抛错 | 返回 shim 内自带的 jQuery（若卡内已加载） |
| `window.parent.getWorldbookNames()` | 跨源抛错 | 返回宿主预注入的世界书名快照（同步） |
| `window.parent.getWorldbook(name)` | 跨源抛错 | 异步经 `postMessage` 向宿主请求，返回只读快照（有大小上限） |
| `window.parent.postMessage(...)` | 正常 | facade 转调原生 `postMessage`，语义不变 |
| `window.parent.document` 等其他属性 | 跨源抛错 | 仍为 `undefined`，不提供 |
| 世界书写入（`replaceWorldbook` 等） | 不可用 | 仍不可用；只有 §2.1-L4-B 的会话副本写入落地后才考虑 |

结合 §3.1：操作手册可解锁；开场切换还需要 L4-B 的写入，facade 只解决“读不到”的问题。

#### 2.3.2 硬性约束

- facade 是**本地对象**，不是父窗口代理：没有 DOM、没有 `document`、没有
  `localStorage`、没有 token，也无法通过它访问宿主的其他属性。
- `window.top` 同步替换为同一 facade；`window.frameElement` 返回 `null`。
- 只暴露显式白名单成员；未列出的属性返回 `undefined`。
- 世界书名与内容属于用户数据，注入前做大小/深度上限；内容默认只读，并受用户开关控制。
- 写入 API 在 L4-B 落地前全部返回 rejected Promise / `false`，并提示只读。
- `postMessage` 必须保留原生语义（绑定到真实父窗口），否则会破坏现有卡片通信。
- 不修改卡内源码，只在 shim 里替换全局属性。

#### 2.3.3 为什么不是同源桥

同源桥意味着卡片能拿到真实的父 `Window`，从而读 DOM、Cookie、storage、调用宿主函数。
facade 反过来：卡片只看到一个**假的、只含白名单方法的普通对象**，真实父窗口仍跨源
不可触达。风险面从“环境级访问”降到“几个显式 API”，因此可以评审、可以限量、可以
按用户开关整体关闭。

#### 2.3.4 落地前提

需要在桌面浏览器与 Android WebView 中实测 `window.parent = facade` 是否生效（`parent`
的可替换性随引擎实现可能不同）；不生效时本项直接放弃，不改卡源作为兜底。

| 操作手册 | 静态 | 静态（模块顶层读 `window.parent.$` 抛错） | 仍静态 | §2.3 facade 提供 `$` 后可解锁，仍属远期 |

| 多开场白 | 可用 | 可用 | 可用 | 由 FlyAI 自带“选择开局”（`开局*` / `序章*`）提供，与卡内“开场切换”无关 |

综合判断：在 L1/L2 与 §2.2 落地、§2.3 尚未落地时，这张卡是**“可玩、可看、不可改”**
——正文对话、MVU 数值推进、只读状态栏、开场美化、头像与配置联网都可用；面板内写入、
开场切换、操作手册、TavernHelper 扩展与同源 `window.parent` 能力仍不可用。§2.3 落地
后可额外解锁操作手册，开场切换仍需 L4-B 的写入。

## 4. 协议与数据安全

### 4.1 两条通道，一条规则

**`srcDoc` 只做启动快照；运行中的状态永远不重写 `srcDoc`。**

- 初始 `{ stat_data: … }` 直接嵌入 shim，保证卡内顶层 `init()` 第一次执行就能读到值，
  避开 iframe `load` 竞态。
- 后续变量/消息变化用 `postMessage` 发给已加载的 iframe，变量变化不触发重载。
- 仅当 `html`、`externalMedia` 或用户点“刷新”时重建 `srcDoc`。
- 所有写入 API 都是只读桩：发宿主 toast，不写回会话。

### 4.2 消息常量

在 `webapp/src/services/st/cardApp.ts` 中定义并导出：

```ts
export const CARD_APP_PROTOCOL_VERSION = 1
export const CARD_MSG_RESIZE = 'flyai-card-resize'   // 现有
export const CARD_MSG_READY = 'flyai-card-ready'
export const CARD_MSG_VARS = 'flyai-card-vars'
export const CARD_MSG_MESSAGE = 'flyai-card-message'
export const CARD_MSG_TOAST = 'flyai-card-toast'
export const CARD_CODE_READ_ONLY = 'read-only'
export const CARD_CODE_VARS_TOO_LARGE = 'vars-too-large'
```

| 方向 | `type` | 载荷 | 说明 |
|---|---|---|---|
| 宿主 → iframe | `flyai-card-vars` | `{ v:1, variables }` | 已归一化为 `{ stat_data: … }` |
| 宿主 → iframe | `flyai-card-message` | `{ v:1, message }` | `getChatMessages` 的实时原文 |
| iframe → 宿主 | `flyai-card-ready` | `{ v:1 }` | DOMContentLoaded/load 后通知宿主补发 |
| iframe → 宿主 | `flyai-card-resize` | `{ height }` | 现有高度上报 |
| iframe → 宿主 | `flyai-card-toast` | `{ v:1, level, text?, code? }` | `code` 可为 `read-only` / `vars-too-large` |

§2.2 的 `flyai-card-fetch` / `flyai-card-fetch-result` / `flyai-card-fetch-abort` 与
§2.3 的 `flyai-card-worldbook` 属后续批次，落地时按同一套来源校验与版本号规则登记。

校验规则：

- iframe 只接受 `e.source === parent` 且 `v === 1` 的已知类型。
- 宿主严格校验 `event.source === iframeRef.current?.contentWindow`，并白名单 `type`、
  `level`，截断 `text`。
- `targetOrigin` 使用 `'*'`：沙箱文档是 opaque origin，无法指定具体 origin；消息只发给
  指定 `contentWindow`，载荷也只有本消息或本卡可见的 MVU 快照。

### 4.3 变量归一化与上限

新增导出函数 `sanitizeCardAppVariables(variables)`，返回
`{ variables, serialized, truncated }`：

- `null`/非对象 → `{ stat_data: {} }`。
- 若传入对象含对象型 `stat_data`，视为完整状态；否则包装成 `{ stat_data: variables }`
  （兼容直接传根对象的调用方）。
- 深拷贝并加保护：循环引用 → `'[Circular]'`；深度、节点、字符串、数组、键数量超限
  → 截断并标记；函数、Symbol、BigInt、非有限数字安全处理。
- `JSON.stringify` 后超过 128KB 或抛错 → 回退 `{ stat_data: {} }`，
  `truncated = true`。
- 不修改入参；`serialized` 用于父子两侧去重。
- 测试与日志只使用合成字段，不打印真实卡内数据。

建议上限：

```ts
export const MAX_CARD_APP_VARIABLES_LENGTH = 128 * 1024
export const MAX_CARD_APP_VARIABLE_DEPTH = 16
export const MAX_CARD_APP_VARIABLE_NODES = 20_000
export const MAX_CARD_APP_VARIABLE_STRING = 32 * 1024
export const MAX_CARD_APP_VARIABLE_ARRAY = 500
export const MAX_CARD_APP_VARIABLE_KEYS = 1_000
export const MAX_CARD_APP_TOAST_LENGTH = 500
```

### 4.4 安全边界不变

- 继续使用
  `sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"`。
- 继续使用 null-origin iframe、`referrerPolicy="no-referrer"`、`loading="lazy"`。
- 不放开 CSP：`connect-src 'none'`、`default-src 'none'` 等保持现状。
- §2.2 的网络桥**不改动 CSP**：它通过 `postMessage` 把请求交给宿主、由服务端发出；
  允许卡片联网不等于允许浏览器直连。
- 卡内脚本读不到宿主 DOM、Cookie、localStorage 和 token。
- 不把 `window.parent` 变成同源桥。§2.3 的 facade 只把 `window.parent` / `window.top`
  指向本地白名单对象，真实父窗口仍跨源不可访问；实施时需单独评审并验证目标 WebView
  的 `[Replaceable]` 行为。
- §2.1 的 L4-B、§2.2 的网络桥与 §2.3 的 facade 都是后续独立批次；任何“直接放开
  CSP”的提案必须单独评审本节，不能以“用户已授权”为由直接放开。§2.2.3 的
  SSRF/去凭据/配额限制属于服务器边界，同样不因用户授权而关闭。

## 6. 数据流与边界

- 后端 `_st_payload` 已提供 `st.mvu.stat_data` 根对象；前端 shim 包装成
  `getAllVariables() => ({ stat_data: … })`，不新增后端字段。
- `MessageList` 已有 `stVariablesFor(message)`：助手消息有 `statData` 快照时用快照，
  否则回退到会话当前 `st.mvu.stat_data`。开场消息没有快照，因此显示当前状态；历史
  助手消息保持各自快照。
- 初始变量写入 `srcDoc`；后续更新只走 `postMessage`，页签、滚动位置、动画不会重置。
- 失败模式：
  - `js_sandbox` 关闭：静态清洗，无数值；预期降级。
  - jQuery CDN 不可达：状态栏初始化失败，HTML/CSS 外壳仍在但无填值；本地打包
    jQuery 留到 L3。
  - 卡内应用超过 `MAX_CARD_APP_LENGTH`：仍显示静态/源码，不执行。
  - 变量循环/过大：归一化兜底为空状态并提示，不让 iframe 卡死。
  - 编辑/删除：`Mvu.replaceMvuData` 拒绝、`alert`/`toastr` 转宿主 toast；状态不变。
  - 网络桥关闭或用户拒绝：`fetch` 以 `TypeError` reject，卡内 `try/catch` 降级；
    不会回退成浏览器直连。
  - 代理被上游拒绝（403/防盗链/需要登录）：按 `blocked` / `upstream` / `too-large` /
    `timeout` 分类回传，卡内可显示对应文案。
- 远期 L4-B 的变量写回不直写 `session.mvu.stat_data`（`recompute_state` 会从消息
  快照重算并覆盖），应校验后挂到消息快照上并标注 `origin: "card"`，与 AI 生成的
  `<UpdateVariable>` 走同一条通道。
- 不修改卡内 HTML/JS 源码，不做字符串重写（例如把 `window.parent` 改成 `window`），
  避免改变卡行为并带来不可控风险。
